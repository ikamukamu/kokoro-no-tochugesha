## 概要

`netlify.toml` の設定に起因して、ISS-053の修正が本番公開されない事象が発生した。
原因は独立した2件で、どちらも `netlify.toml` の修正で解消した。

1. ビルドスキップの判定が直前1コミットしか見ておらず、コード変更を取りこぼした
2. `publish` 未指定によりリポジトリ全体が配信対象となり、`#` を含むファイル名で
   デプロイ全体が失敗した

（2026-09-09、ISS-053の公開確認時に発覚。実装が先行し、事後にMDを作成）

## 背景

### 事象

2026-09-08にISS-053（ご案内モーダルの文言見直し）をCommit・Pushしたが、
翌9-09にスマホの実機で確認したところ、モーダルの表示は旧文言のままだった。
公開サイトを直接取得して確認したところ、配信されているHTMLが旧版であり、
ブラウザキャッシュではなく実際に未デプロイであることが判明した。

### 原因1：ビルドスキップ判定が浅い

修正前の設定は以下だった。

```toml
ignore = "git diff --quiet HEAD^ HEAD -- . ':!docs'"
```

`HEAD^ HEAD` は直前の1コミットのみを見る。9-08のPushは2回に分かれており、

1. `fix(ISS-053): ご案内モーダルの文言見直し`（index.html を変更）
2. `docs: ISS-053公開に伴うISS一覧・リリース履歴の更新`（docsのみ）

2回目のPushにより1回目のビルドがキャンセルされ、Netlifyは最新コミット（＝docsのみ）
だけを評価してスキップと判定した。結果、index.htmlの変更はどのデプロイにも
含まれないまま取り残された。

### 原因2：公開範囲がリポジトリ全体

`publish` の指定がなく、リポジトリルートがそのまま配信対象になっていた。
そのため `docs/` 配下も公開されており、9-08に追加した
`docs/ekicho-dayori/#3_v1.pptx` がビルドを失敗させた
（Netlifyは `#` `?` を含むファイル名を配信できない）。

原因1を回避しても、この時点では原因2でビルドが失敗する状態だった。
2つの原因が重なっていたため、切り分けに時間を要した。

## 目的

コード変更が確実にデプロイされる状態に戻し、同じ取りこぼしが再発しないようにする。
あわせて、公開する必要のないファイルを配信対象から外す。

## 要件

- ビルドスキップの判定基準を「最後にデプロイ成功したコミットからの差分」に変更する
- 配信対象を、公開に必要なファイル（`index.html` / `assets/`）のみに限定する

## 設計方針

修正後の `netlify.toml`。

```toml
[build]
  command = "rm -rf dist && mkdir -p dist && cp index.html dist/ && cp -r assets dist/"
  publish = "dist"
  ignore = "git diff --quiet $CACHED_COMMIT_REF $COMMIT_REF -- index.html assets"
```

## 判断理由

- **スキップ判定**：`$CACHED_COMMIT_REF`（最後にデプロイ成功したコミット）を基準に
  すれば、途中に何コミット挟まっても未デプロイの変更を取りこぼさない。
  キャッシュクリア時などで変数が空の場合はコマンドがエラー終了するため、
  ビルドが実行される側に倒れる（安全側）
- **公開範囲**：`#` のファイル名を変更して個別に対処する案もあったが、それでは
  同種の問題が再発しうるうえ、そもそも `docs/` を配信する必要がない。
  配信対象をホワイトリスト方式にすることで、ファイル名の制約から恒久的に解放される
- **判定対象**：ignoreの対象を `. ':!docs'`（docs以外すべて）ではなく
  `index.html assets`（配信対象そのもの）に変更した。publishの内容と判定基準が
  一致するため、docs以外にファイルが増えても意図しないビルドが起きない

## 実装メモ

- 修正当時PCが手元になく、GitHubのWeb UIから `netlify.toml` を直接編集した
- 6.68MBのpptxはバイナリのためWeb UIでリネームできず、この経路を選んだ
  （結果的に、リネーム自体が不要になった）
- `index.html` は `docs/` 配下のファイルを一切参照していないことを確認済み。
  参照は `assets/` 配下の画像・音声のみ

## 懸念事項

- **[[ISS-024]]（駅長だよりonWEB）への影響**：`docs/` は今後Web配信されないため、
  アプリから駅長だよりを配信する場合は、配信対象のファイルを `assets/` 配下に
  置く必要がある。設計時に留意すること
- `docs/ekicho-dayori/` の `#2_v13.pptx` `#3_v1.pptx` は、デプロイ上は無害に
  なったが、Obsidianのリンク記法 `[[...]]` では `#` が見出し指定として
  解釈されるためリンクが機能しない。フォルダ内の他ファイルの命名規則
  （`01_2026-07.md` 形式）に揃えたリネームが望ましい
- `dist/` はビルド時に生成される一時ディレクトリだが `.gitignore` に未記載。
  ローカルでビルドを試す場合は追加が必要
