## 概要

呼吸法を完了した際に、ランダムな二字熟語（例：「浄化」「生存」）と、駅長ペンギン＆列車のスタンプ風グラフィックを表示する演出を追加する。[[ISS-027]]（呼吸法フィールドのモーダル化）から切り出した派生ISS。

## 背景

[[ISS-027]]の検討過程で、以前構想していた「ペンギンが呼吸に同調して動く」演出（4-7-8呼吸のベンチ瞑想、4-4-4-4呼吸の四角歩行）は、瞑想中の集中を妨げる可能性があるため見送った。ただし素材として魅力的なため、呼吸法完了後の一瞬だけ見せる「ご褒美演出」として転用することにした。

### スコープの見直し（2026-09-12）

保志さんから、スタンプ機能について①スタンプの見た目・②押印アニメーション・③カレンダー形式の履歴閲覧（呼吸スタンプ帳）・④収集要素のあるアルバム機能（スタンプコレクション帳）、という4つのアイデアが出た。規模・性質の違いから以下のように整理した。

- **①②＋記録保存の土台、③カレンダー履歴閲覧**：本ISS（ISS-042）のスコープとする
- **④コレクション帳（路線図テーマ、レア/シークレットスタンプ）**：ゲーム性のある別機能に近く、規模も大きいため、[[ISS-056]]として切り出し、本ISSのスコープ外とする

現状、瞑想セッションの完了記録は一切保存されていない（`finishMindfulnessTimer()`は完了画面を表示するのみ）。③を実現するには、完了のたびに記録（日付・呼吸法・時間・引いた熟語）を保存する仕組みが必要であり、この「記録の土台」は④（ISS-056）が将来参照する上でも必要になるため、本ISSで先に用意しておく。

### スタンプ画像の制作方針（2026-09-12、複数回の試行錯誤の末に確定）

当初はこの環境にある画像編集ツール（Pillow）で、既存の駅長ペンギン・列車素材を組み合わせて自作する方針で試作を重ねた（数値計算で円からの文字・列車のはみ出しを防ぐなど、細部の作り込みを行った）。しかし、

- 手作業でのグランジ加工（かすれた縁の表現）が、ノイズを使った力技では「汚れ」にしか見えず、狙った質感にならなかった
- 列車の配置・向き・煙の表現など、細部の調整に何度も往復が発生し、完成度が頭打ちになった

一方、保志さんが**Gemini**（画像生成AI）に依頼したサンプル（「NR赤坂駅・浄化」スタンプ）が、線路のかすれた質感・全体の完成度ともに大幅に上回っていたため、**基本画像の生成はGeminiに任せる方針に転換**した。

この方針転換に伴い、スタンプの構成要素を以下のように整理した。

- **スタンプ共通テンプレート（デザイン言語として統一）**：外周の円、乗車券・切符風の四角いタグ
- **スタンプごとに焼き込む内容（1枚の完成画像として都度Geminiに生成依頼）**：二字熟語、No.（番号）、駅名、駅長ペンギンのポーズ、横に添える駅・鉄道関連のイラスト
- **アプリ側で動的に重ねる内容**：完了日時（Gemini生成画像には空欄を用意しておき、その位置にCSS/HTMLでテキストを重ねる）※2026-11-06に見直し。日付は入れないことにした（下の「背景と日付の見直し」）

生成に使うプロンプトテンプレートは [[スタンプ生成プロンプトテンプレート]] を参照。

### 背景と日付の見直し（2026-11-06〜09）

**日付は入れない**：背景を足す段階で、ユーザーから「日付はいらなくない？」という指摘があり、日付の空白とアプリ側での日付の重ねは、やめることにした。
スタンプは、二字熟語・切符・ペンギンで成り立つ。日付が要らなくなったため、画像ごとの重ね位置の調整の手間もなくなる（下の「懸念事項」「実装メモ」のうち、日付に関する項目は、この見直しで不要になった）。

**背景（添える絵）は、必須の部品ではなく、あとから足せる任意の層にする**：
- 背景を生成AIに単独で作らせると、枠・ペンギン・文字・切符の画風と合わず、子供向けのおもちゃのような絵になった（銀河鉄道の2枚で確認）。コードで描く案も試したが、絵の力が足りなかった（ユーザー：「無理無理 レベルが違う」）。
- ユーザーの提案：「枠とセットでグループ化されたものを何パターンか用意しておく感じで、ペンギンを張り、文字と切符更新をすれば完成、みたいなの。」
- ユーザーが示した手順：「・まず背景無しでそれ以外は完成しているスタンプを作る ・それをもとに元画像はいじらず、背景を足して完成してもらう（統一感がある画像が差し込まれる） ・良い感じのものができたらペンギン部分も塗り足した背景だけを作成してもらう」
- 完成したスタンプ（背景なし）を画像生成AIに渡して背景を足してもらい、返ってきた絵から、背景部分（月・星）だけを取り出す。枠・ペンギン・文字・切符は、こちらの原画をそのまま上に重ねる（AIに描き直されても影響しない）。

**背景だけ、色を変える（2色にする）**：
- ユーザーの言葉：「ビビッドピンクで目をかわいさとゴシック感を出しつつ、ゴールドできらびやかなアクセント」「ココロの途中下車がベースとして夜のプラットフォームで暗い背景だから、そこに押すスタンプとしてピンクとゴールドって良いよね」
- 枠・ペンギン・文字・切符はピンク `#f72572`、背景だけゴールド `#F5D77A`（3段階を比べ、ユーザーが「Bでいこう」と選んだ）。
- 暗い画面に押す前提なので、ペンギンの白い部分（透過）は、画面の暗い色が見えるままでよい。
- No.003に、夜空（月と星）の背景を、仮決めで当てた（Geminiの1回目の絵から、月と五角形の星を取り出した）。

**将来の余地**：背景を別の層にしてあるので、星がゆっくり瞬くなどの動きを、あとから足せる。ユーザーの言葉：「背景だけ少し動くってのも良いけど（秋の葉っぱみたいに）そこまではやめた方が無難だもんね。」今回は、実装しない。

**世界観の参考（雰囲気のみ）**：ユーザーが目指す背景のイメージは、「ゴシックレトロファンシーダークビビッドウォームがごちゃごちゃしないで表現されている」もの（アニメ『輪るピングドラム』の高倉家・ヒマリの部屋の場面）。作品の場面・キャラクターは描かず、「幕で囲う」「中央を明るく、まわりを暗く」「大きく読める形」という作り方だけを借りる。

### スタンプの構成単位について

「二字熟語」「駅名」「ポーズ」「横のイラスト」は、要素ごとに独立してランダムに組み合わせるのではなく、**あらかじめワンセットで完成した「スタンプ」を複数種類作っておき、その中からランダムに1つを選ぶ**方式とする（要素の独立ランダム化は、組み合わせ次第で絵のバランスが崩れるリスクがあるため採用しない）。

## 設計方針

### 完了画面のレイアウト変更（2026-09-12確定）

現在の完了画面（`breathing-complete-view`）は、上から「りんごのアイコン」「お疲れさまでした」「ゆっくりと、いつもの時間へ戻りましょう。」「ホームへ戻るボタン」の順に並んでいる。

これを、スタンプを画面中央に大きく押せるよう、以下の構成に変更する。

```
変更前                          変更後
┌─────────────┐          ┌─────────────┐
│   🍎（りんご）  │          │              │
│  お疲れさまでした │    →     │   （スタンプが  │
│  ゆっくりと…    │          │    ここに押される）│
│ [ホームへ戻る]  │          │              │
└─────────────┘          │ [ホームへ戻る]  │
                          │  お疲れさまでした │
                          │  ゆっくりと…    │
                          └─────────────┘
```

- りんごのアイコン（`fa-apple-whole`）を削除し、その位置をスタンプの表示・押印アニメーション用の余白にする
- 「お疲れさまでした」「ゆっくりと、いつもの時間へ戻りましょう。」のテキストは、**「ホームへ戻る」ボタンの下**に移動する（順序：スタンプ余白 → ホームへ戻るボタン → お疲れさまでした → ゆっくりと…）
- これにより、視覚的な優先度を「スタンプ（達成の証）＞行動（ホームへ戻る）＞説明テキスト」の順にする

### 押印のタイミング（2026-11-16確定）

- **ISS-068（クリスマス演出）より、本ISSを先に進める**。ユーザー：「押印の実装（ISS-042）を先に進めたい」
- **スタンプ画像**：`assets/stamps/stamp_001.png`〜`005.png`、1024×1024px、透過PNG。001〜005の順は、本ISSのNo.と同じ。円の中心を基準に切り出した正方形（元データは3800×3800px）。2026-11-16に、リポジトリの`assets/stamps/`へ置いた

## 懸念事項

- 二字熟語の選定基準（セルフケアの文脈にふさわしい言葉か）は、[[スタンプ生成プロンプトテンプレート]]内の候補ストックから選ぶ運用とするが、最終的なリストは未確定
- 押印アニメーションは、CSSアニメーションで作る想定（追加のライブラリは使わない）。「動きを減らす」設定の端末では、動かさず、ふわっと表示するだけにする
- カレンダービューの設置場所（きっぷ保管庫の中か、独立した画面か）は未決定。「きっぷ保管庫」の名称見直しの議論と合わせて検討が必要
- ~~スタンプ画像ごとに日付の重ね位置がずれる可能性があり、量産時の運用コスト（座標調整の手間）が読めていない~~（2026-11-06に、日付を入れないことにしたため、解消）
- スタンプ画像の書き出しは、PowerPointで枠が上に寄った大きな正方形（4400×4400px）になるため、円の中心を基準に3800×3800pxへ切り出している（2026-11-13、5枚とも同じ範囲）。アプリで使う大きさ（1024px角を想定）と置き場所・ファイル名は、未確認。アプリに登録する前に決める
- 暗い画面に押す前提で、実際の画面に置いたときの見え方（ピンクとゴールドの組み合わせ、ペンギンの白の抜け方）は、アプリ上で確認していない
- スタンプ画像は、1枚約0.5MB（5枚で約2.4MB）。完了画面で1枚だけ読み込むため、初回表示には影響しない見込み。重ければ、[[ISS-066]]と同様に、WebPへの変換を検討する
- ④（ISS-056）と将来的にデータ構造を共有するため、本ISSで設計する記録データの形式が、ISS-056の要件を先取りして考える必要がある
