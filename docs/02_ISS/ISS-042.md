## 概要

呼吸法を完了した際に、ランダムな二字熟語（例：「浄化」「生存」）と、駅長ペンギン＆列車のスタンプ風グラフィックを表示する演出を追加する。[[ISS-027]]（呼吸法フィールドのモーダル化）から切り出した派生ISS。

## 背景

[[ISS-027]]の検討過程で、以前構想していた「ペンギンが呼吸に同調して動く」演出（4-7-8呼吸のベンチ瞑想、4-4-4-4呼吸の四角歩行）は、瞑想中の集中を妨げる可能性があるため見送った。ただし素材として魅力的なため、呼吸法完了後の一瞬だけ見せる「ご褒美演出」として転用することにした。

### スコープの見直し（2026-09-12）

保志さんから、スタンプ機能について①スタンプの見た目・②押印アニメーション・③カレンダー形式の履歴閲覧（呼吸スタンプ帳）・④収集要素のあるアルバム機能（スタンプコレクション帳）、という4つのアイデアが出た。規模・性質の違いから以下のように整理した。

- **①②＋記録保存の土台、③カレンダー履歴閲覧**：本ISS（ISS-042）のスコープとする
- **④コレクション帳（路線図テーマ、レア/シークレットスタンプ）**：ゲーム性のある別機能に近く、規模も大きいため、[[ISS-056]]として切り出し、本ISSのスコープ外とする

現状、瞑想セッションの完了記録は一切保存されていない（`finishMindfulnessTimer()`は完了画面を表示するのみ）。③を実現するには、完了のたびに記録（日付・呼吸法・時間・引いた熟語）を保存する仕組みが必要であり、この「記録の土台」は④（ISS-056）が将来参照する上でも必要になるため、本ISSで先に用意しておく。

### スタンプ画像の制作方針（2026-09-12、複数回の試行錯誤の末に確定）

当初はこの環境にある画像編集ツール（Pillow）で、既存の駅長ペンギン・列車素材を組み合わせて自作する方針で試作を重ねた（数値計算で円からの文字・列車のはみ出しを防ぐなど、細部の作り込みを行った）。しかし、

- 手作業でのグランジ加工（かすれた縁の表現）が、ノイズを使った力技では「汚れ」にしか見えず、狙った質感にならなかった
- 列車の配置・向き・煙の表現など、細部の調整に何度も往復が発生し、完成度が頭打ちになった

一方、保志さんが**Gemini**（画像生成AI）に依頼したサンプル（「NR赤坂駅・浄化」スタンプ）が、線路のかすれた質感・全体の完成度ともに大幅に上回っていたため、**基本画像の生成はGeminiに任せる方針に転換**した。

この方針転換に伴い、スタンプの構成要素を以下のように整理した。

- **スタンプ共通テンプレート（デザイン言語として統一）**：外周の円、乗車券・切符風の四角いタグ
- **スタンプごとに焼き込む内容（1枚の完成画像として都度Geminiに生成依頼）**：二字熟語、No.（番号）、駅名、駅長ペンギンのポーズ、横に添える駅・鉄道関連のイラスト
- **アプリ側で動的に重ねる内容**：完了日時（Gemini生成画像には空欄を用意しておき、その位置にCSS/HTMLでテキストを重ねる）

生成に使うプロンプトテンプレートは [[スタンプ生成プロンプトテンプレート]] を参照。

### スタンプの構成単位について

「二字熟語」「駅名」「ポーズ」「横のイラスト」は、要素ごとに独立してランダムに組み合わせるのではなく、**あらかじめワンセットで完成した「スタンプ」を複数種類作っておき、その中からランダムに1つを選ぶ**方式とする（要素の独立ランダム化は、組み合わせ次第で絵のバランスが崩れるリスクがあるため採用しない）。

## 目的

- 呼吸法をやり遂げた達成感を、世界観に沿った演出で表現する
- ランダム性を持たせることで、毎回の完了体験に変化をつける
- 完了記録を蓄積し、後から振り返れるようにする（カレンダー表示）

## 要件

### ①スタンプのデザイン

- Geminiで生成した、完成品の「スタンプ画像」を複数種類用意する（構成：外周円＋切符風タグ＋二字熟語＋No.＋駅名＋駅長ペンギンのポーズ＋横のイラスト、色はビビッドピンク`#f72572`の単色）
- 各スタンプ画像には、完了日時をあとから重ねられるよう、あらかじめ空白のスペースを確保しておく（プロンプトで明示的に指定する）
- 呼吸法完了時、用意したスタンプ画像の中からランダムに1つを選んで表示し、空白部分に完了日時をCSS/HTMLで重ねて表示する

### ②押印アニメーション

- 呼吸完了後、完了画面に大きくスタンプが「押印される」アニメーションを表示する
- 演出の候補：スタンプが上から降りてきて押される動き、または小さな星が飛ぶようなファニーな演出。具体的な実装方法は設計方針で検討する

### ③呼吸スタンプ帳（カレンダー履歴）

- 完了のたびに、記録（日付・選択した呼吸法・セッション時間・引いたスタンプの種類）を保存する
- 「呼吸スタンプ帳」（名称は仮）として、カレンダー形式で日付ごとにスタンプを確認できるビューを用意する
- スタンプをクリックすると、その日の実施詳細（実施日時・呼吸法・タイマーの時間等）を確認できる
- 「きっぷ保管庫」という名称自体の見直しは本ISSのスコープ外とする（別途検討）

## 設計方針

### 完了画面のレイアウト変更（2026-09-12確定）

現在の完了画面（`breathing-complete-view`）は、上から「りんごのアイコン」「お疲れさまでした」「ゆっくりと、いつもの時間へ戻りましょう。」「ホームへ戻るボタン」の順に並んでいる。

これを、スタンプを画面中央に大きく押せるよう、以下の構成に変更する。

```
変更前                          変更後
┌─────────────┐          ┌─────────────┐
│   🍎（りんご）  │          │              │
│  お疲れさまでした │    →     │   （スタンプが  │
│  ゆっくりと…    │          │    ここに押される）│
│ [ホームへ戻る]  │          │              │
└─────────────┘          │ [ホームへ戻る]  │
                          │  お疲れさまでした │
                          │  ゆっくりと…    │
                          └─────────────┘
```

- りんごのアイコン（`fa-apple-whole`）を削除し、その位置をスタンプの表示・押印アニメーション用の余白にする
- 「お疲れさまでした」「ゆっくりと、いつもの時間へ戻りましょう。」のテキストは、**「ホームへ戻る」ボタンの下**に移動する（順序：スタンプ余白 → ホームへ戻るボタン → お疲れさまでした → ゆっくりと…）
- これにより、視覚的な優先度を「スタンプ（達成の証）＞行動（ホームへ戻る）＞説明テキスト」の順にする

## 判断理由

- **④（コレクション帳）を切り出した理由**：路線図テーマのアルバムUI、レア/シークレットスタンプの抽選ロジックなど、①②③とは別次元の設計・実装が必要なため。ISS-052の教訓（スコープを詰め込みすぎると設計・実装ともに停滞する）を踏まえた
- **画像生成をGeminiに任せる方針にした理由**：この環境（Claude）のPillowによる自作では、グランジ質感や細部の完成度に限界があった。Geminiが生成したサンプルの方が明確に高品質だったため
- **要素の独立ランダム化ではなく完成品セットから選ぶ方式にした理由**：二字熟語・駅名・ポーズ・イラストを別々にランダム化すると、組み合わせ次第で絵のバランスが崩れるリスクがある。ワンセットの完成品として作る方が、Geminiへの依頼もしやすく、品質を保ちやすい

## 実装メモ

- スタンプ画像はPNG形式で、完了日時を重ねる位置（座標）をあらかじめ決めておく必要がある（Gemini生成時にプロンプトで空白位置を指定しても、毎回微妙にレイアウトが変わる可能性があるため、画像ごとに個別に座標を調整することになる可能性がある）
- 完了記録の保存先・データ構造は、既存の`saveLocalData`等の仕組みに準じる想定（実装時に確定）
