# ISS-033 プリセットをマイコーピングとして登録

|項目|内容|
|---|---|
|状態|公開済|
|優先度|中〜高|
|担当|自分|

> このテンプレートは「最初から全部埋める」ことを目的としない。 ISSの進行に合わせて少しずつ育てる運用とする。

## 概要

処方箋やプリセット一覧で見たコーピングを、その場で自分のマイコーピングとして 新規登録できるようにする。「そのまま追加」と「内容を編集してから追加」の 両方を扱うが、いずれも**新しいマイコーピングを新規作成する処理**であり、 元のプリセットには一切手を加えない。

## 背景

チャピ・黒子との相談で、以下の指摘があった。

- 処方箋で「散歩する」が表示された後に「役に立ちそう！［自分のコーピングに 追加］」と出せると自然。プリセットは「ヒント集」であり、気に入ったものだけ 自分のノートへ写す、という体験が『ココロの途中下車』らしい
- 既存プリセットをコピー編集して自分用に登録できるようにする提案もあった （例：「散歩する」→「近所の公園を10分歩く」）

この「コピーして自分用に変える」方法には複数の実装パターンが考えられたため、 検討した結果を下記「判断理由」に残す。

## 目的

- プリセット（駅長のヒント）を見て気に入ったものを、その場で自分のコーピング に取り込めるようにする
- 取り込む際、そのまま登録するか、自分用に編集してから登録するかを選べる
- プリセットは「共有のヒント集」という役割を保ち、個人による直接編集や 追記の対象にはしない

## 要件

- 処方箋・プリセット一覧の各コーピング表示に、以下2つの導線を設ける
    - 「このまま追加」：プリセット内容をそのまま新しいマイコーピングとして保存
    - 「自分用に変えて追加」：プリセット内容を初期値とした登録フォームを開き、 編集してから新しいマイコーピングとして保存
- いずれの操作も、内部的には[[ISS-032]]の新規登録処理を利用する （新しいレコードを作るだけで、既存データの更新・追記は行わない）
- 元のプリセットは変更されない・他の利用者にも影響しないことを保証する

## 設計方針

[[コーピング機能刷新構想]]の設計原則（登録はできるだけ簡単に、探しやすさを 優先）に沿う。

- 「そのまま追加」「自分用に変えて追加」は、いずれも[[ISS-032]]の 「タイトル＋詳細」データ構造を使った新規登録処理として実装する （プリセットの内容を初期値として登録フォームに渡すかどうかの違いのみ）
- プリセットとマイコーピングの表示上の区別（[[ISS-031]]の「駅長のヒント」 「わたしのコーピング」の分離）と導線を整合させる
- ボタンは処方箋実行画面・プリセット一覧の両方に設置する想定

## 判断理由

プリセットを自分用に調整する方法として、以下3案を検討した。

|案|内容|評価|
|---|---|---|
|① 新規追加|プリセットを初期値として新しいマイコーピングを作成する|採用|
|② 直接編集|プリセット自体を書き換える（個人用の上書きデータを持つ）|不採用|
|③ コメント追記|プリセットに個人メモを追記する|不採用|

**①を採用した理由：**

- プリセットは共有されるヒントとして扱い、利用者による直接編集や個人情報の 追記は行わない、という役割分担を崩さない
- ②は「元の提案を書き換えたのか、自分用のコピーを作ったのか」が利用者から 見て分かりにくくなる。将来プリセット自体を更新する場合にも、個人の上書き データとの整合をとる必要が生じ、データ設計が複雑になる
- ③は「コメント」という別概念を増やすことになり、現段階では過剰
- 利用者が内容を自分向けに調整したい場合は、プリセットを初期値として 新しいマイコーピングを作成する、という方針に統一する

**「そのまま追加」と「編集して追加」を同一ISSに含めた理由：**

- どちらも「プリセットを基にマイコーピングを新規作成する」という同じ処理 であり、違いは保存前に編集フォームを開くかどうかだけ
- ISSを分ける基準は操作ステップ数ではなく、「独立して価値を提供できるか」 「別のデータ構造が必要か」「別々にリリースする意味があるか」で判断する。 この2操作はいずれも該当しないため、分割しない

ボタンのスタイル（min-h、border、色）は、既存の`coping-used-btn`等と統一する。

### 2. 「そのまま追加」の処理（新規関数）

```js
function addPresetAsMyCoping(presetId) {
    const item = getCopingListItems().find(record => record.id === presetId);
    if (!item) { showToast('コーピングが見つかりませんでした。', 'error'); return; }
    const now = new Date().toISOString();
    const record = { id: 'my_coping_' + crypto.randomUUID(), stateTag: item.stateTag, title: item.title, effect: item.effect || '', detail: item.detail || '', createdAt: now, updatedAt: now };
    if (!saveLocalData(MY_COPING_STORAGE_KEY, record)) { showToast('マイコーピングに追加できませんでした。', 'error'); return; }
    expandedCopingId = record.id;
    activeCopingFilter = 'all';
    renderCopingList();
    showToast('マイコーピングに追加しました。', 'success');
}
```

- 元のプリセット（`copingSkillsDatabase`）は一切変更しない
- 新しいIDで別レコードとして保存する（`saveMyCoping`の新規登録時と同じ構造）

### 3. 「自分用に変えて追加」の処理（既存フォームを流用・拡張）

`openMyCopingForm(id = null)`に、プリセットの内容を初期値として渡せるよう引数を追加する。

```js
// 変更後のシグネチャ
function openMyCopingForm(id = null, prefill = null) {
    let target = null;
    if (id) {
        target = getMyCopingRecords().find(item => item.id === id);
        if (!target) { showToast('編集するマイコーピングが見つかりませんでした。', 'error'); return; }
    }
    editingMyCopingId = id; // idがnullなら常に「新規作成」として保存される
    const source = target || prefill;
    populateMyCopingStateOptions(source?.stateTag || getSelectedCopingState());
    document.getElementById('my-coping-title').value = source?.title || '';
    document.getElementById('my-coping-effect').value = source?.effect || '';
    document.getElementById('my-coping-detail').value = source?.detail || '';
    document.getElementById('my-coping-form-title').textContent = id ? '💊 編集' : '💊 新規追加';
    document.getElementById('my-coping-modal').classList.remove('hidden');
    document.getElementById('my-coping-title').focus();
}
```

呼び出し側（「自分用に変えて追加」ボタン）：

```js
function openCopingEditAndAddForm(presetId) {
    const item = getCopingListItems().find(record => record.id === presetId);
    if (!item) { showToast('コーピングが見つかりませんでした。', 'error'); return; }
    openMyCopingForm(null, { title: item.title, effect: item.effect || '', detail: item.detail || '', stateTag: item.stateTag });
}
```

- `editingMyCopingId`が`null`のまま`saveMyCoping()`が呼ばれるため、保存時は既存の「新規作成」分岐が実行され、新しいレコードとして保存される（プリセットは変更されない）

### 4. イベント委譲の追加（既存の`#coping-list`クリックハンドラ内）

既存の`editButton`/`deleteButton`/`usedButton`/`addPlaceholderButton`の判定と同じ書き方で、`coping-add-asis-btn`・`coping-add-edit-btn`の判定を追加し、それぞれ`addPresetAsMyCoping(id)`・`openCopingEditAndAddForm(id)`を呼ぶ。`addPlaceholderButton`の判定・準備中トーストは不要になるため削除する。

## レビュー・フィードバック（v2・2026-09-07）

公開後の指摘。

1. **ボタンのアイコンに統一感がない**：「やってみた」（💊絵文字）「そのまま追加」（＋アイコン）「自分用に変えて追加」（✎絵文字）と、絵文字とアイコンフォントが混在している
2. **「自分用に変えて追加」の名称**：「そのまま追加」と対にするなら「編集して追加」の方が自然。どちらも最終的には「マイコーピングに追加する」行為なので、末尾を「追加」で揃えたい。またスマホ幅だとボタンテキストが2行に折り返ってしまうため、短縮したい

## 要件（v2追加）

### ボタンアイコンの統一

- 「やってみた」「そのまま追加」「編集して追加（旧：自分用に変えて追加）」の3ボタンで、アイコンの種類（絵文字 or Font Awesomeアイコン）を統一する
- 既存のアプリ全体でFont Awesomeアイコン（`fa-solid`等）が多用されているため、絵文字（💊・✎）をFont Awesomeアイコンに置き換える方向で統一する（例：やってみた→`fa-check`、そのまま追加→`fa-plus`、編集して追加→`fa-pen`。具体的なアイコン種類の選定は実装時に任せる）

### 「自分用に変えて追加」の名称変更

- 「自分用に変えて追加」を**「編集して追加」**に変更する（「そのまま追加」と対になる、簡潔な表現に統一）
- ボタンテキストが短くなることで、スマホ幅でも1行に収まることを確認する

## レビュー・フィードバック（v3・2026-09-07）

公開後、実際に使う中で気づいた重複登録の問題。

1. **「そのまま追加」の多重クリックで重複登録できてしまう**：同じプリセットに対して「そのまま追加」を複数回押すと、全く同じ内容のマイコーピングが何個でも作られてしまう
2. **プリセットとその複製が並んで表示され邪魔**：「そのまま追加」した後、「すべて表示」で見ると、元のプリセット（駅長のヒント）と、複製されたマイコーピング（わたしの登録）の両方が表示され、同じ内容が2つ並ぶ
3. **「編集して追加」も内容が近い複製になりがち**：完全一致ではないため厳密な防止はできないが、何らかの配慮をしたい

## 要件（v3追加）：重複登録の防止・整理

「そのまま追加」（完全に同一内容）と「編集して追加」（内容が変わりうる）とで、対応の強さを分ける。

### データ構造：`sourcePresetId`の追加

- マイコーピングのレコードに`sourcePresetId`フィールドを追加する
- 「そのまま追加」で作成したレコードには、元のプリセットの`id`を`sourcePresetId`として保存する
- 「編集して追加」で作成したレコードにも、同様に元のプリセットの`id`を`sourcePresetId`として保存する（内容は変わっても、由来は記録しておく）
- 通常の新規登録（プリセット由来でないもの）は`sourcePresetId`を`null`のままにする

### 「そのまま追加」：厳密な重複防止

- `addPresetAsMyCoping(presetId)`実行時、既存のマイコーピングに同じ`sourcePresetId`を持つレコードが**既に存在する場合は、新規作成せず**、トースト「すでに追加済みです」を表示し、既存のレコードを展開表示する（`expandedCopingId`を既存レコードのidにする）
- 存在しない場合のみ、新規作成する（現状の処理を維持）

### 表示の整理：「すべて表示」では複製元プリセットを隠す

- 「すべて表示」フィルタで一覧を組み立てる際、`sourcePresetId`が一致するマイコーピングが既に存在するプリセットは、一覧から除外する（同じ内容が2つ並ぶのを防ぐ）
- ただし「駅長のヒント集」フィルタ（プリセットのみの一覧）では、**除外せずそのまま表示する**（プリセット一覧としての網羅性を優先する）

### 「編集して追加」：ゆるやかな注意喚起

- `saveMyCoping()`で新規レコードを保存する際（編集中の既存レコードを更新する場合は対象外）、同じ状態タグ内に**同じタイトル**（前後の空白を除き、大文字小文字を区別しない比較）のマイコーピングが既に存在する場合、確認ダイアログ（例：「同じタイトルの登録がすでにあります。追加しますか？」）を表示し、OKされた場合のみ保存を続行する
- 確認ダイアログの見た目は、既存の削除確認モーダル（`closeMyCopingDeleteModal`まわり）のスタイルに合わせる（ブラウザ標準の`confirm()`ではなく、アプリの見た目に統一されたモーダルを使う）

## 要件（v4追加）：登録済みバッジの表示

各フィルタでの表示ラベルの組み合わせを、以下の通りに整理する。

|フィルタ|対象|表示ラベル|
|---|---|---|
|すべて表示|マイコーピング（そのまま追加/編集して追加/通常登録）|「わたしの登録」のみ|
|マイコーピング|同上|「わたしの登録」のみ|
|駅長のヒント集|プリセット（未追加）|「駅長のヒント」のみ|
|駅長のヒント集|プリセット（`sourcePresetId`が一致するマイコーピングが既に存在する＝追加済み）|「駅長のヒント」＋**「マイコーピング登録済み」**の2つのラベルを併記|

- 「マイコーピング登録済み」バッジは、既存の「駅長のヒント」「わたしの登録」ラベルと並べて表示する（配色は控えめなもの、既存の緑系ラベルとは別の色にして視覚的に区別できるようにする。具体的な配色は実装時に任せる）
- このバッジは「駅長のヒント集」フィルタでのみ表示されればよく、「すべて表示」「マイコーピング」フィルタでの表示ロジックに変更は不要
