# ISS-034 コーピングのタグ・分類の仕組み

|項目|内容|
|---|---|
|状態|検討中|
|優先度|中|
|担当|自分|

> このテンプレートは「最初から全部埋める」ことを目的としない。 ISSの進行に合わせて少しずつ育てる運用とする。

## 概要

現状、コーピングは単一のカテゴリ（5個）で分類されているが、これを複数タグを 持てるデータ構造に変更する。**カテゴリの「仕組み」を変えるのが本ISSの主目的で あり、タグの「中身」（具体的な分類名）の精査は範囲に含めない。**

## 背景

現状の5カテゴリ（ストレスから離れる／誰かに助けを求める／気持ちを整理する／ 認知を変化させる／気晴らしをする）は、NotebookLMに一覧を渡し、Geminiに 分割してもらったもので、実際の利用傾向から検証されたものではない。

チャピとの相談で、これらの分類軸が混在している可能性が指摘された。

- 誰かに助けを求める：行動・手段
- 認知を変化させる：作用
- 気晴らしをする：目的や効果
- ストレスから離れる：対処方針

将来的には、単一カテゴリではなく、以下のような複数軸のタグの方が 「必要なコーピングをすぐ見る」という目的に合う、という方向性が[[コーピング機能刷新構想]] に記載されている。

- 方法：身体を動かす、人と関わる、考える、休む
- 目的：落ち着く、離れる、整理する、元気を出す
- 状況：仕事中、家、外出中、寝る前
- 負荷：すぐできる、少し時間が必要

### その後の経緯（2026-08-17〜09-08）

- **2026-08-17**：ISS-031の設計過程で、実際に実装されたコーピングの5カテゴリ（バクバク心臓／イライラ気分／ガチガチ思考／チクチク視線／ポッカリ虚無）が、本ISS背景に記載の「現状の5カテゴリ」（ストレスから離れる、等）と一致しないことが判明。実際のカテゴリは「今の症状・状態」という単一の軸で揃っており、当初の「軸が混在している」という問題意識の前提が崩れていた
- **2026-09-03**：前提の崩れを受けて本ISSを一旦「保留」に変更。一方で、この見直しの過程で「状態とは別に、『なりたい状態・欲しい効果』という軸から探せると良いのでは」というアイデアが挙がり、[[ISS-052]]として分岐・起票した
- **2026-09-03（ISS-052内）**：ISS-052で「効果（作用）」軸によるタブ切り替えUIまで設計したが、実装着手前の見直しで、UIの複雑化・振り分けの一貫性の無さに加え、「なりたい自分を想像する体験は、コーピングよりもセルフトーク・言葉のサプリの役割に近い」という本質的な気づきがあり、ISS-052は保留に変更された
- **2026-09-08**：ISS-052の教訓（①UIを複雑化させない、②コーピングの役割は「今すぐ実行できるか」という実務的な軸に留める）を踏まえ、本ISSを「時間」「場所」という2つの実務的な軸に絞って再検討することにした

## 目的

- コーピングに、今すぐ実行できるかどうかを判断する材料となるタグ（時間・場所）を持たせる
- タグを使った並び替え・グループ表示を、既存の一覧UIを圧迫しない形で提供する
- タグの「中身」は今回、時間・場所の2軸に確定させる（当初想定していた方法・目的・状況・負荷という4軸の複数タグ構想は採用しない。ISS-052の教訓を踏まえ、感情・効果寄りの軸は対象外とする）

## 要件

### タグの軸（2026-09-08確定）

- **時間**：すぐできる／少し時間がかかる（単一選択）
- **場所**：どこにいてもできる／誰もいないところでする／道具や設備があるところ（単一選択）
- 「方法」軸（からだを動かす・考え方を変える等）は、分類の切り分けが曖昧でユーザーが能動的に使う軸として弱いと判断し、**採用しない**
- 「効果・なりたい状態」軸は、ISS-052の教訓によりコーピングの役割から外れるため、**採用しない**

### データ構造

- コーピング1件につき、`duration`（時間タグ、単一値）・`location`（場所タグ、単一値）を持たせる
- 複数タグ（配列）ではなく、**各軸1つずつの単一選択**とする（ISS-052で複数タグ化による分類の曖昧さを経験したため、シンプルさを優先する）
- タグは初回登録時に必須にしない（[[ISS-032]]の「登録はできるだけ簡単に」という設計原則に従う。マイコーピングの新規登録フォームでは任意入力とする）
- プリセット49件には、あらかじめ時間・場所タグを付けておく（全件分の振り分けは「関連ノート」の[[コーピングタグ振り分け案_v2_20260908]]を参照）

### UI：並び替え・グループ化プルダウン（Planner風）

- 既存の状態タブ＋フィルタ＋アコーディオン一覧の構成は変更しない
- 一覧の上部に、**「並び替え」ボタンを1つだけ**追加する
- ボタンを押すと、以下の並び替え・グループ化の選択肢が表示される
    - 状態順（現状のまま、デフォルト）
    - 時間順（すぐできる／少し時間がかかる、の見出しでグループ化）
    - 場所順（どこにいてもできる／誰もいないところでする／道具や設備があるところ、の見出しでグループ化）
- いずれかを選ぶと、一覧が選んだ軸の見出し（グループ）ごとに再構成される。Microsoft Plannerの「グループ化」切り替えと同様の体験を想定
- 常設のフィルタ・タブ要素を増やさないことで、ISS-052で経験したUIの複雑化を回避する

## 設計方針

[[コーピング機能刷新構想]]の設計原則（後から育てられる設計にする）に沿う。

- データ構造は「時間」「場所」それぞれ単一選択の2軸とする（複数タグ配列ではない。詳細は「判断理由」参照）
- UI上は、タグ選択を必須にせず、任意入力・後から追加できる形にする
- 既存の状態タブ・フィルタ機能には手を加えず、その上に「並び替え」という独立した軸を追加する形にする

### 画面構成（2026-09-08確定）

既存の一覧に、件数表示（`coping-hit-count`）と同じ行に「並び替え」ボタンを追加する。新しい行は増やさない。

```
┌─────────────────────────────────┐
│ すべて表示｜マイコーピング｜駅長のヒント集 │ ← 既存のフィルタ（変更なし）
├─────────────────────────────────┤
│ ⇅ 並び替え：状態順          3枚 │ ← 左に並び替えボタン、右に件数（既存の行を活用）
├─────────────────────────────────┤
│ ▸ コーピングタイトルA              │
│ ▸ コーピングタイトルB              │
└─────────────────────────────────┘

「並び替え」タップで小さいメニューが開く
┌──────────────┐
│ ● 状態順（デフォルト）│
│ ○ 時間順           │
│ ○ 場所順           │
└──────────────┘

「時間順」を選ぶと一覧がこう変わる：
┌─────────────────────────────────┐
│ ⇅ 並び替え：時間順          8枚 │
├─────────────────────────────────┤
│ すぐできる                        │ ← グループ見出し
│ ▸ コーピングタイトルA              │
│ ▸ コーピングタイトルC              │
│                                  │
│ 少し時間がかかる                  │ ← グループ見出し
│ ▸ コーピングタイトルB              │
└─────────────────────────────────┘
```

- 状態タブ・フィルタ（すべて表示／マイコーピング／駅長のヒント集）は今まで通り機能する。「並び替え」は、その**絞り込んだ範囲の中身をどう並べるか**だけを変える、独立した軸として扱う
- 「状態順」（デフォルト）は現状の見た目のまま（グループ見出しなし、フラットな一覧）
- 「時間順」「場所順」を選んだときのみ、該当タグの値ごとにグループ見出しを立てて一覧を再構成する

## 判断理由

- **単一選択×2軸にした理由**：ISS-052で複数タグ（1件が複数の効果グループに属する）を採用した際、分類の一貫性が崩れ、実装前の見直しで保留に至った。同じ轍を踏まないよう、今回は「時間」「場所」それぞれ1件につき1つの値だけを持つ、シンプルな構造にする
- **並び替えプルダウン方式にした理由**：フィルタチップを追加する案（既存のフィルタ行にタグの選択肢を並べる）も検討したが、ISS-041・ISS-031で余白確保に苦労した経緯を踏まえ、常設のUI要素を増やさない方式を優先した。「並び替え」ボタン1つだけを追加し、押したときだけ選択肢が現れる方式（Microsoft Plannerのグループ化切り替えと同様の体験）であれば、普段の画面占有を増やさずに済む
- **件数表示の行に相乗りした理由**：`coping-hit-count`用の行がすでに存在し、左側に余白があったため、新しい行を増やさずに済む配置とした

## 実装メモ

Codexへの実装依頼用メモ。`index.html`のコーピング機能まわりに実装する。

### 1. データ構造

- `copingSkillsDatabase`の各項目（プリセット49件）に、`duration`（時間タグ、"すぐできる"または"少し時間がかかる"）・`location`（場所タグ、"どこにいてもできる"／"誰もいないところでする"／"道具や設備があるところ"）を追加する
- 値は本ドキュメントの「全49件のタグ振り分け」表の通り設定する
- マイコーピングのレコードにも同じく`duration`・`location`フィールドを持たせる（任意入力、未入力可）

### 2. 「並び替え」ボタンの追加（HTML変更）

`coping-hit-count`のある行（739行目付近）を、左右に要素を並べる行に変更する。

```html
<!-- 変更前 -->
<p id="coping-hit-count" class="text-right text-[10px] font-bold text-gray-500" aria-live="polite"></p>

<!-- 変更後 -->
<div class="flex items-center justify-between">
    <button id="btn-coping-sort" type="button" class="flex items-center gap-1 text-[10px] font-bold text-gray-600" aria-haspopup="true" aria-expanded="false">
        <i class="fa-solid fa-arrow-up-wide-short"></i>
        <span id="coping-sort-label">並び替え：状態順</span>
    </button>
    <p id="coping-hit-count" class="text-[10px] font-bold text-gray-500" aria-live="polite"></p>
</div>
<!-- 並び替えメニュー（普段は非表示、ボタン押下で表示） -->
<div id="coping-sort-menu" class="hidden ...">
    <button type="button" class="coping-sort-option" data-sort="state">状態順</button>
    <button type="button" class="coping-sort-option" data-sort="duration">時間順</button>
    <button type="button" class="coping-sort-option" data-sort="location">場所順</button>
</div>
```

メニューの開閉・選択中表示の見た目（チェックマーク等）は、既存のドロップダウンパターン（新規登録フォームの状態タグ選択など）を参考に実装してよい。

### 3. 一覧レンダリングの分岐（`renderCopingList`の拡張）

- 現在の並び替え軸を保持する状態変数（例：`activeCopingSort`、初期値`'state'`）を新設する
- `renderCopingList()`内で、`activeCopingSort`が`'state'`の場合は現状通りフラットな一覧を描画する
- `'duration'`または`'location'`の場合は、表示対象のコーピング一覧を該当フィールドの値でグループ化し、グループ見出し（例：「すぐできる」「少し時間がかかる」）を挟んで描画する
- グループの並び順：時間軸は「すぐできる→少し時間がかかる」、場所軸は「どこにいてもできる→誰もいないところでする→道具や設備があるところ」の順で固定する
- `duration`・`location`が未設定のマイコーピングは、各グループ化表示において「その他」または「未分類」という末尾グループにまとめる
- 状態タブ・フィルタ（すべて表示／マイコーピング／駅長のヒント集）による絞り込みは、並び替え軸に関わらずこれまで通り適用してから、グループ化・描画を行う

### 4. 件数表示・イベント委譲

- `coping-hit-count`の件数計算ロジックは変更不要（絞り込み後の件数を表示するだけなので、並び替え軸には影響されない）
- `btn-coping-sort`のクリックでメニューの表示・非表示をトグルし、`.coping-sort-option`のクリックで`activeCopingSort`を更新して`renderCopingList()`を再実行、メニューを閉じ、`coping-sort-label`のテキストを選択内容に更新する

## アイデアメモ（今回のスコープ外・ISS-032関連）

- **マイコーピング登録時の文字色カスタマイズ**：登録・編集フォームで、コーピングごとに表示色を選べるようにしたいという要望あり。実装自体は軽量（`color`フィールド追加＋一覧表示時の反映）だが、自由なカラーピッカーではなく、世界観に合う4〜6色程度のスウォッチから選ぶ形にすることを推奨。ISS-032（登録UX改善）のアイデアとして記録し、別途落ち着いたタイミングで検討する

## 懸念事項

- 既存のマイコーピング（ユーザー登録分）には時間・場所タグが無いため、並び替え時にどのグループに入れるか（例：「未分類」グループを作るか、デフォルト値を与えるか）の扱いを実装時に決める必要がある
- 「並び替え」ボタンの具体的な見た目・配置は次回詰める（本ISSでは方向性のみ確定）
- [[ISS-031]]の一覧表示・アコーディオン構造とタグ構造が連動するため、[[ISS-031]]側の実装（renderCopingList等）との整合を取りながら進める

## 完了条件

- コーピング49件（プリセット）に、時間・場所タグが付与されている
- 一覧上部の「並び替え」ボタンから、状態順／時間順／場所順を切り替えられる
- 時間順・場所順を選ぶと、一覧が該当するグループの見出しで再構成される
- マイコーピングの新規登録フォームで、時間・場所タグを任意入力できる（未入力でも登録できる）
- タグなしでも登録できる状態が維持されている
