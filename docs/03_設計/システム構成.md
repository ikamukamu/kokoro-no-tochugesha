# システム構成

このノートは「ココロの途中下車」を構成するシステム・サービス全体の役割と
連携フローを管理する。作成日：2026-07-01（OneNoteより移行、Obsidian移行に
伴い一部更新）。

## 構成図

```
              📁 docs/（Obsidian Vault）
         （設計・運営・プロジェクト管理）
                        │
              仕様・要件・アイデア
                        ▼
                   🤖 Codex
                 （ソースコード編集）
                        │
                index.html を更新
                        ▼
              💻 GitHub Desktop / Git CLI
              （Commit / Push）
                        │
                        ▼
                 ☁ GitHub
   （ソースコード・履歴・プロジェクト資産を管理）
                        │
                  Push を検知
                        ▼
                🌍 Netlify
            （自動デプロイ・公開）
                        │
                        ▼
                    👤 利用者
                        │
                  アクセス情報
                        ▼
         📊 Cloudflare Web Analytics
              （アクセス解析）
```

**OneNote時代からの変更点：** 正本の管理場所を`OneNote`から`docs/`
（Obsidian Vault、GitHubリポジトリ内）に変更した。理由・経緯は[[開発ルール]]
の「情報の正本」を参照。

## システム一覧

| システム | 役割 |
|---|---|
| docs/（Obsidian） | 設計・運営情報の管理（正本はGitHubリポジトリ内） |
| Codex | ソースコード編集 |
| GitHub Desktop / Git CLI | Commit / Push |
| GitHub | ソースコード管理 |
| Netlify | Webサイト公開（自動デプロイ） |
| Cloudflare Web Analytics | アクセス解析 |
| Firebase / Firestore | クラウド保存（**休眠中**、下記参照） |
| Google AI Studio（Gemini API） | セルフトークAI相談・AI思考ほぐし等で使用 |

## データ保存の構成

[[Ver1.0機能カタログ]]の技術メモより。

- 保存系は、ローカル記録・クラウド記録・バックアップ対象キーがコード上で
  分かれており、CBT／セルフトーク／良いこと日記の3系統を扱う
- クラウド側はFirebase認証後にFirestoreの`cbt_records` / `talk_records` /
  `threegoods_records`を購読する構成として実装されている
- **ただし現在、Firestore連携は休眠中。** コードは実装済みだが、
  `__firebase_config`等の設定値を注入する仕組みがリポジトリ内に存在しない
  ため、通常のNetlify配信では動作しない。現在の正式な保存先はLocal Storage
  （`AGENTS.md`の「実装上の既知事項」参照）
- Firestoreを有効化する場合は、Local Storageの既存データを自動同期する処理・
  競合解決ルール・書き込み失敗時の通知を、あわせて設計し直す必要がある
