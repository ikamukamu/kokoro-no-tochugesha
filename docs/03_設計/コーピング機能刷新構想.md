# コーピング機能刷新構想

このノートは、マイコーピング機能の再構成（ISS-031〜034）に着手する前段階として、 「コーピング機能は誰のために、何を一番しやすくする機能なのか」を明文化し、 今後のISS判断の基準とするための構想メモです。

**まだ確定した要件ではありません。** 実装対象は本メモから改めてISSとして 切り出します。ISS化するまでの間、思いついたアイデアを蓄積する場所として使います。

## コーピング機能の目的

ユーザーが自分に合ったコーピングを少しずつ集め、必要なときに迷わず取り出せる ようにする。プリセットと処方箋は、その発見と選択を助ける。

「自分のコーピング／プリセットのどちらが主でどちらが従か」という主従関係では なく、**どちらもユーザーの選択に委ねられる**という設計方針とする （例：全部／自分のみ／既存のみ／お気に入り、のようなフィルタ表示）。

## 各要素の役割

|要素|役割|
|---|---|
|マイコーピング|自分のための実用品|
|プリセット|発見のヒント|
|処方箋|思い出す・選ぶための提案機能|
|カテゴリ・タグ|探しやすくする補助|

## 設計原則

今後ISS-031〜034に限らず、コーピング機能に関わるすべてのISSがこの原則に 沿っているか判断する基準とする。

- 登録はできるだけ簡単にする
- 後から育てられる設計にする
- 探しやすさを優先する
- 世界観は機能を邪魔しない範囲で加える

## 設計方針の当たり（ISS-031着手前に決めておきたいこと）

- **表示はフィルタ方式にする**：全部／自分のみ／既存のみ／お気に入り、を 切り替えられるようにし、主従を作らない。デフォルト（全部表示）では、 ユーザー登録のコーピングが上位に来るようソートし、埋もれを防ぐ
    
    理由：ユーザー自身が登録したコーピングは、自分に合う可能性が高いため、 既存コーピングより優先表示する。ただしフィルタで既存のみ・自分のみを 自由に切り替えられるため、主従関係を固定するわけではない。
    
- **データは「タイトル＋詳細」の2階層にする**：
    
    - タイトル：一覧に付箋のように並ぶ短い単語（例：「散歩」）。一次登録で必須
    - 詳細：クリックで開く。内容・メモなど。後から追加でよい
    - これにより「気軽に登録」と「あとから育てる」を両立する
- **タグは複数持てるデータ構造にしておく**：
    
    - 裏側（データ構造）は複数タグに対応させておく
    - ただし表側（UI）は、初回登録ではタグなしでも保存可能にし、複雑さを見せない
    - プリセット側にはあらかじめタグを付けておいてもよい
- **分類軸は「カテゴリ」1本ではなく複数軸を想定する**： 現状の5カテゴリ（ストレスから離れる／誰かに助けを求める／気持ちを整理する／ 認知を変化させる／気晴らしをする）は、方法・目的・状況などの軸が混在している 可能性がある。将来的には以下のような複数軸のタグを想定：
    
    - 方法：身体を動かす、人と関わる、考える、休む
    - 目的：落ち着く、離れる、整理する、元気を出す
    - 状況：仕事中、家、外出中、寝る前
    - 負荷：すぐできる、少し時間が必要
    
    ※軸の確定は今すぐ行わない。カテゴリの「中身」は実データが溜まってから 見直す（[[ISS-034]]で検討）。ここで先に決めるのは「複数タグを持てる 構造にしておく」ということだけ。
    

## 見送る／後段にするアイデア（アイデアメモ）

思いついたが、一覧・登録・分類という本質が見えにくくなるため、初期段階では 実装しない。ISS-031〜034が形になった後、改めてISS化を検討する。

- 色・アイコン・テーマによるコーピングのデコレーション
- お気に入り機能・ピン留めによる優先表示
- フィルタボタンに駅長ペンギンのアイコンを使った視覚効果
- 検索・絞り込み機能

## ISSの進め方（暫定）

先に決めるもの（本メモの範囲）：

- コーピング機能刷新構想（本ノート）
- 最低限のデータ構造（タイトル＋詳細、複数タグ対応）
- 現行データとの互換性

その後の実装：

- [[ISS-031]]：マイコーピング一覧・詳細表示
- [[ISS-032]]：簡易登録・後から編集
- [[ISS-033]]：プリセットからマイコーピングへ追加
- [[ISS-034]]：タグ・分類の仕組み

その後（見送りアイデアから改めてISS化）：

- ピン留め・お気に入り
- 装飾（色・アイコン・テーマ）
- 検索・絞り込み
