# コーピング機能刷新構想

このノートは、マイコーピング機能の再構成（ISS-031〜034）に着手する前段階として、 「コーピング機能は誰のために、何を一番しやすくする機能なのか」を明文化し、 今後のISS判断の基準とするための構想メモです。

**まだ確定した要件ではありません。** 実装対象は本メモから改めてISSとして 切り出します。ISS化するまでの間、思いついたアイデアを蓄積する場所として使います。

## コーピング機能の目的

ユーザーが自分に合ったコーピングを少しずつ集め、必要なときに迷わず取り出せる ようにする。プリセットと処方箋は、その発見と選択を助ける。

「自分のコーピング／プリセットのどちらが主でどちらが従か」という主従関係では なく、**どちらもユーザーの選択に委ねられる**という設計方針とする （例：全部／自分のみ／既存のみ／お気に入り、のようなフィルタ表示）。

## 各要素の役割

|要素|役割|
|---|---|
|マイコーピング|自分のための実用品|
|プリセット|発見のヒント|
|処方箋|思い出す・選ぶための提案機能|
|カテゴリ・タグ|探しやすくする補助|

## 設計原則

今後ISS-031〜034に限らず、コーピング機能に関わるすべてのISSがこの原則に 沿っているか判断する基準とする。

- 登録はできるだけ簡単にする
- 後から育てられる設計にする
- 探しやすさを優先する
- 世界観は機能を邪魔しない範囲で加える

## 設計方針の当たり（ISS-031着手前に決めておきたいこと）

- **表示はフィルタ方式にする**：全部／自分のみ／既存のみ／お気に入り、を 切り替えられるようにし、主従を作らない。デフォルト（全部表示）では、 ユーザー登録のコーピングが上位に来るようソートし、埋もれを防ぐ
    
    理由：ユーザー自身が登録したコーピングは、自分に合う可能性が高いため、 既存コーピングより優先表示する。ただしフィルタで既存のみ・自分のみを 自由に切り替えられるため、主従関係を固定するわけではない。
    
- **データは「タイトル＋詳細」の2階層にする**：
    
    - タイトル：一覧に付箋のように並ぶ短い単語（例：「散歩」）。一次登録で必須
    - 詳細：クリックで開く。内容・メモなど。後から追加でよい
    - これにより「気軽に登録」と「あとから育てる」を両立する
- **タグは複数持てるデータ構造にしておく**：
    
    - 裏側（データ構造）は複数タグに対応させておく
    - ただし表側（UI）は、初回登録ではタグなしでも保存可能にし、複雑さを見せない
    - プリセット側にはあらかじめタグを付けておいてもよい
- **分類軸は「カテゴリ」1本ではなく複数軸を想定する**： 現状の5カテゴリ（ストレスから離れる／誰かに助けを求める／気持ちを整理する／ 認知を変化させる／気晴らしをする）は、方法・目的・状況などの軸が混在している 可能性がある。将来的には以下のような複数軸のタグを想定：
    
    - 方法：身体を動かす、人と関わる、考える、休む
    - 目的：落ち着く、離れる、整理する、元気を出す
    - 状況：仕事中、家、外出中、寝る前
    - 負荷：すぐできる、少し時間が必要
    
    ※軸の確定は今すぐ行わない。カテゴリの「中身」は実データが溜まってから 見直す（[[ISS-034]]で検討）。ここで先に決めるのは「複数タグを持てる 構造にしておく」ということだけ。
    

## 現状把握：実装済みコードとドキュメントの齟齬（2026-08-17発見）

ISS-031〜034の着手順序を検討する過程で、実際の`index.html`の`copingSkillsDatabase`を確認したところ、ISS-034.mdに記載されている「現状の5カテゴリ」の説明と、実装済みのカテゴリが一致していないことが判明した。

- ISS-034.mdの記載：ストレスから離れる／誰かに助けを求める／気持ちを整理する／認知を変化させる／気晴らしをする（NotebookLM/Geminiによる初期プラン）
- 実際のコード：⚡動悸・緊張・心臓バクバク／😡怒り・理不尽なイライラ／🏆完璧主義「ねばならない」の罠／👥他人の目（嫌われてるかも犬）／🔋意欲低下・おっくう・体が動かない

実際の5カテゴリは「今の症状・状態」という単一の軸で揃っており、ISS-034.mdが想定していた「軸が混在している」という問題意識とは前提が異なる。ISS-034への着手時は、まずこのドキュメントとコードの齟齬を解消するところから始める必要がある。

## 2026-08-17の設計相談メモ

コーピング機能の見直しについて相談した内容。この時点ではまだISS化していない、構想段階のメモだった。

### 状態選択（症状ベースの入口）は維持しつつ、直感性を改善

- 「まず状態を選んでもらう」という導線自体は機能的に有効なので維持する
- ただし現状のテキストラベルは直感的に選びにくい。「動悸」「怒り」「完璧主義」「他人の目」「意欲低下」くらいの短い一言＋イラスト（アイコン）のボタンにすることで、直感的な選択のしやすさを改善する

### 方法・行動ベースでの検索という第2の入口

- 「解消したい方向性は決まっているが、具体的な方法を知りたい」というニーズには、状態（症状）ベースではなく方法・行動ベースで探せる導線があると良い
- これは元々[[コーピング機能刷新構想]]で想定していた「方法・目的・状況・負荷」の複数軸タグ構想（[[ISS-034]]）と方向性が一致する。状態選択と方法検索、2つの入口を用意するイメージ

### ランダム抽選3件方式の位置づけ再検討

- コーピングは「今すぐ実行可能な行動」を選ぶものであり、文脈・状況とズレた提案は無価値どころか有害（例：「水で手を洗う」が出ても、手を洗える状況でなければ意味がない）
- 「言葉のサプリ」（条件を決めずランダムに何か格言が欲しい、という探し方）とは逆の性質の機能であり、コーピングにおいてはランダム性より「見やすい一覧から自分で選べる」ことの方が有用性が高い

### 表示方式：段階的なドリルダウンUI（検討過程）

- 当初はMacのファインダーのカラム表示のような、選択すると右側に次の階層が展開していく表示方式を検討した
- → 2026-08-21の相談で、スマホの縦長画面には横タブ＋アコーディオンの方が適していると判断し、方式を変更（詳細は[[ISS-031]]参照）

### 使用ログの記録

- コーピング詳細画面に「使用した」（文言は要検討）ボタンを追加し、押すときっぷ保管庫に記録を残す
- いつ・どのコーピングを・どのくらいの頻度で使っているか、というデータが振り返り材料として蓄積できる。ISS-031の一覧・編集機能や、将来の「育つコーピング帳」構想（最終使用日・使用頻度の表示）とも接続する

## 2026-08-21の設計確定（ISS-031へ落とし込み済み）

8/17のメモをもとに、ISS-031の画面設計として以下を確定した。詳細・完成形は[[ISS-031]]を参照。

- **画面構成**：状態タブ（5つ、アイコン＋ラベル、横並び）を上部に常駐 → 選択中タブの補足テキスト＋追加登録ボタン → フィルタ（全部／自分のみ／既存のみ／お気に入り）→ アコーディオン形式の一覧、という縦積み構成に確定
- **詳細表示**：別画面に遷移せず、タップした場所でアコーディオンがその場で展開する方式に確定（Finder風の横展開案は縦長スマホ画面には不向きと判断し不採用）
- **ランダム抽選**：撤廃を決定。「おみくじ的な別機能として残すか」は結論を出さず、保留事項として残す（下記参照）

## 保留事項（未決定）

- ランダム抽選を、セルフトークの「お守りライブラリ」のおみくじ機能と同じような、独立したサブ機能として残すかどうか。今回は撤廃を優先し、この案自体は採用も却下もしていない
- 「使用した」ボタンの文言（仮置きのまま。「実践した」「試した」等の代案あり）

思いついたが、一覧・登録・分類という本質が見えにくくなるため、初期段階では 実装しない。ISS-031〜034が形になった後、改めてISS化を検討する。

- 色・アイコン・テーマによるコーピングのデコレーション
- お気に入り機能・ピン留めによる優先表示
- フィルタボタンに駅長ペンギンのアイコンを使った視覚効果
- 検索・絞り込み機能

## ISSの進め方（暫定）

先に決めるもの（本メモの範囲）：

- コーピング機能刷新構想（本ノート）
- 最低限のデータ構造（タイトル＋詳細、複数タグ対応）
- 現行データとの互換性

その後の実装：

- [[ISS-031]]：マイコーピング一覧・詳細表示
- [[ISS-032]]：簡易登録・後から編集
- [[ISS-033]]：プリセットからマイコーピングへ追加
- [[ISS-034]]：タグ・分類の仕組み

その後（見送りアイデアから改めてISS化）：

- ピン留め・お気に入り
- 装飾（色・アイコン・テーマ）
- 検索・絞り込み
