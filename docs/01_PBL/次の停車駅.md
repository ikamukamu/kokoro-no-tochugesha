# 次の停車駅（バックログ運用ルール）

このノートは、実装候補（プロダクトバックログ）の運用ルールを定義する。 実データは`01_PBL/次の停車駅_*.xlsx`（Excel）で管理する。ISSごとの詳細な 設計・判断理由は`02_ISS/ISS-XXX.md`を参照（索引は[[ISS一覧]]）。

## なぜExcelとMarkdownを分けているか

優先順位・状態によるフィルタ・並べ替えを多用する運用のため、実データは Markdown表ではなくExcelで管理する。ISSの詳細な設計意図・判断理由は Excelでは書きにくいため、`02_ISS`のMarkdownノートで管理する。

- **Excel**：一覧管理（優先順位・状態・フィルタ・並べ替え）
- **Obsidian（`02_ISS`）**：個々のISSの詳細・判断理由・実装結果

## Excelの構成

シート「次の停車駅（実装候補）」に、1行＝1ISSとして記録する。

|列|内容|
|---|---|
|ID|`="ISS-"&TEXT(ROW()-1,"000")`の数式で自動採番。**手入力しない**|
|区分|新機能／機能改善／UI/UX／デザイン／コンテンツ／不具合／技術基盤／その他|
|状態|検討中／対応予定／設計中／実装中／Commit済／公開済／保留／却下|
|優先度|5 優先／4 高／3 中／2 低／1 保留|
|機能名|短い名称|
|概要|内容の説明|
|起点|自分／AI対話／GitHub Issue／動作確認／ユーザー／家族／その他|
|登録日|起票した日付|
|公開Ver|利用者へ公開したバージョン番号（[[開発ルール]]の採番基準に従う）|
|公開日|公開した日付|
|依存ISS|他のISS番号との依存関係。複数ある場合はカンマ区切り|
|備考|対応する`02_ISS/ISS-XXX.md`へのパスなど|

区分・状態・起点・優先度はプルダウン（データ入力規則）で選択する。選択肢は シート「LSIT」で管理している。

## 状態の定義

```
検討中 → 対応予定 → 設計中 → 実装中 → Commit済 → 公開済
                                              ↓
                                            保留 ⇄ 検討中（いつでも戻せる）
                                            却下
```

- 保留にした案件は、いつでも「検討中」へ戻せる
- 却下は原則として復活させない（再検討する場合は新規ISSとして起票）

## ID・ファイル命名の対応

ExcelのID（`ISS-XXX`）と、`02_ISS/ISS-XXX.md`のファイル名は必ず一致させる。 新しいISSをExcelに追加したら、対応する`02_ISS/ISS-XXX.md`も [[ISSテンプレート]]から作成する（逆に、Markdownだけ作ってExcelに未記載、 という状態を作らない）。

## 新規ISS起票の流れ

1. Excelに1行追加（区分・状態・優先度・機能名・概要・起点・登録日を記入）
2. IDが自動採番されるので、そのIDで`02_ISS/ISS-XXX.md`を [[ISSテンプレート]]から作成
3. Excelの「備考」欄に、対応するMarkdownファイルへのパスを記載
4. 依存関係がある場合、Excelの「依存ISS」列とMarkdown側の「関連ISS」欄の 両方に記載する（どちらか一方だけにならないよう注意）

## ISSを分ける基準

操作ステップ数ではなく、以下で判断する（[[ISS-033]]の検討過程で確立した基準）。

- 独立して価値を提供できるか
- 別のデータ構造が必要か
- 別々にリリースする意味があるか

これに当てはまらない場合は、無理に分割せず1つのISSにまとめる。
