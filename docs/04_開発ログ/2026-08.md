## 2026-08-05〜06 呼吸法フィールドのモーダル化（ISS-027）

### 概要

かねてから設計を進めていたISS-027（呼吸法フィールドのモーダル化）を、 デザイン確定→初回実装→3回の実機レビュー→Commit・Pushまで完了させ、 v1.0.6として本番公開した。

### 実施内容

**デザイン確定（8/5）**

- 時計クリックの誘導演出（虹色ガイドリング＋デジタル文字切替）をVisualizer でモックアップ、モーダル終了操作（×は確認ダイアログ、時間経過は確認なし） を確定

**初回実装・1回目レビュー（8/5）**

- Codexが実装。実機（スマホ）で確認したところ、時計オーバーレイ演出が 切符メニューと重なる・世界観に浮くなどの問題が発覚し撤回
- 代替として駅長ペンギンのタップ案も検討したが、ISS-023で既にクリック リアクションが実装済みのため競合。発車標のテキストクリック方式に変更
- ガイドリングの単色化、ボタン色、フォントサイズなどの微調整を反映

**2回目レビュー（8/5）**

- タイトル文言、セッション時間選択（30秒刻み）の追加、ガイドサークルの 破線問題を確認
- リンゴの形がカスタムdivでは丸くポップになりすぎる問題が発覚。旧HTML （station_scene.png統合前）を調査し、当時`fa-apple-whole`という Font Awesomeアイコンを使っていたことを発見。ゼロから形を作るのでは なく、既製アイコンを復活させる方針に転換

**3回目レビュー（8/6）**

- 発車標のテキスト・見た目（ビビッドピンクの枠）、ガイドサークルの サイズ・破線廃止、リンゴのサイズ調整・色変更（深い赤→淡いグレー、 ライト/ダークモード両対応）、一時停止／再生ボタンの位置変更、 サイクル数表示の削除を反映

**Commit・Push（8/6）**

- Commit `f0a52d7`：`feat(ISS-027): 呼吸法フィールドをモーダル化`
- v1.0.6として本番公開、実サイトで動作確認
- 副次的な発見：ホーム画面の縦幅が縮んだことで、以前隠していた列車の 線路が見えるようになった。この見え方は好ましく、今後は意図的に線路が 見えるよう背景の高さを調整したいという新しい要望に繋がった

### 目的

長らく検討していたISS-027を実際にリリースまで持っていき、開発フローが Obsidian運用下でも問題なく機能することを確認する。

### 所感

今回のリンゴのデザイン迷走は良い教訓になった。「より丸く」という抽象的な 指示だけでCSSの形状調整を繰り返すより、**過去の実装に同じ課題への答えが 残っていないか先に調べる**方が、結果的に近道だった。旧HTMLに `fa-apple-whole`という答えがそのまま残っていたのは象徴的で、今後も 「ゼロから作る前に、過去のコードや会話に前例がないか確認する」という 姿勢を持ちたい。

3回にわたる実機レビューのサイクル（実装→スマホで確認→気になる点を リストアップ→ISS更新→再依頼）も、今回でかなり定着してきた。スクリーン ショットを都度共有してもらえると、言葉だけでは伝わりにくい微妙な色味や 配置のズレも正確に反映できる。

## 2026-08-06〜08 銀河鉄道のグラフィック刷新（ISS-025）

### 概要

線路の表示範囲拡大、列車アニメーションの全面刷新（白い線画デザイン、 夜空を斜め上に飛行、月と重なる演出、軌跡パーティクル）を実施し、 v1.0.7として本番公開した。

### 実施内容

**線路の表示範囲拡大・夜空拡張**

- `station_scene.png`表示コンテナの比率を画像本来の`2:1`に修正し線路を 表示（副作用で駅長ペンギンの位置がズレたが修正済み）
- `station_scene.png`自体は変更せず、CSSで空エリアを追加してヘッダーを 縦に拡張。月・切符メニューの位置は維持し、駅舎等が相対的に下がる形に

**列車デザインの刷新（3回の画像生成試行）**

- 初回（写実的な模型調）→2回目（紺色塗りつぶし、車両サイズ調整）を経て、 「白い線画（星のきらめき調）」の方向へ転換
- Gemini生成版はチェック柄の透過処理に失敗（チェック柄の明るい四角と 白線画が同じ明度で区別不可）。単色黒背景での再生成を依頼し、KlingAI 生成版で成功

**アニメーションの調整（多数回の実機フィードバック）**

- 進行角度・車体の向き・出現位置・速度・重なり順など、実機で確認しては 微調整を繰り返す形で収束させた。特に「進行方向と車体角度の不一致」 「切符メニューを過ぎた地点での速度低下バグ」など、言葉の指示だけでは 伝わりにくい・予期しない副作用が複数見つかった

**軌跡パーティクル・発光演出**

- 軌跡パーティクルは、量を10個→大幅増加→過剰→適正、発生源やロジック を含め何度か往復して収束
- 参考動画（Kling.AI生成）を見て「列車本体の発光＋周囲の微粒子」という 演出（②）にも挑戦したが、明滅・輪郭の強調表示・想定外の綿毛状の光 など、指示と結果のズレが大きく、3回試行した末に撤回。軌跡パーティ クル（①）のみを採用して区切りとした

**Commit・Push**

- Commit `b386efa`：`feat(ISS-025): 銀河鉄道のグラフィック刷新`
- v1.0.7として公開、実機で最終確認

### 目的

「銀河鉄道」というテーマの視覚的な質感を、station_scene.pngの緻密さに 見合うレベルまで引き上げる。

### 所感

今回、特に学びが大きかったのはアニメーション演出（軌跡・発光）の やり取りだった。「量を増やして」「もう少し○○を」というような相対的な 指示は、想定より大きく／小さく振れやすく、結果を見てから逆方向に戻す やり取りが何度か発生した。今後同種の調整では、可能なら「元の何倍」 「具体的な個数」など、より定量的な指示を心がけたい。

もう一つの学びは、静止画の参考資料よりも「動画」の参考資料の方が、 アニメーション演出の意図を正確に伝えられるということ。参考動画 （Kling.AI生成）を見て初めて「ボケ光」という言葉の実態が「列車本体の 発光＋周囲の微粒子」だと分かった。次回以降、動きを伴う演出を依頼する 際は、可能な限り動画または近い参考動画を先に探す方が、往復を減らせる かもしれない。

うまくいかなかった演出（列車本体の発光）を無理に完成させず、区切りを つけて次に進む判断も、今回は適切だったと思う。「メニュー画面の改修で 見え方が変わるかもしれない」という不確実性がある中で、時間をかけすぎ ないのは良いバランス感覚。

## 2026-08-08〜09 発車標エリアのアイコンループ・光の縁取り演出（ISS-044）

### 概要

呼吸法モーダルへの入り口（発車標エリア）の文言修正と演出追加を行い、 v1.0.8として本番公開した。当初「マーキー演出」として着手したが、途中で 方針を全面転換し、「アイコンループ＋枠の発光」という形に着地した。

### 実施内容

**方針転換**

- 当初、ピングドラムの発車標演出をモチーフに、テキストがスクロールする マーキー演出を検討・実装したが、「メニュー項目のテキストは常時表示が 必須」という構造的な問題に気づき、全面的に不採用とした
- 代案として、時計→リンゴ→駅長ペンギンのアイコンをループさせる演出と、 ピンクの枠が光る演出（新規要素・高さを増やさない）に転換

**駅長ペンギンアイコンの制作（複数回の試行）**

- 初回版（帽子の星バッジ等を含む）は小サイズ（20〜30px）で判別困難と 判明。簡略化を依頼したが、チャピからの2案は帽子の欠落／顔の判別困難と それぞれ問題があった
- Kling.AIで生成し保志さんが手動調整した「線画のみ」版を最終採用。 時計・リンゴと同じ「線のみ」のスタイルで統一感を確保

**光の縁取り演出（実装方式を2度転換）**

- SVGで「枠を光が一周する」方式 → ほぼ見えない（クリッピングが原因と Codexの調査で判明）
- conic-gradientで回転させる方式に変更 → 目立ちすぎる／速度のムラで 違和感
- 「回転」自体をやめ、`box-shadow`による「枠全体が呼吸するように明滅 する」方式に転換 → 強さ・範囲・間隔を複数回微調整し収束

**Commit・Push**

- Commit `140e9e4`：`feat(ISS-044): 発車標エリアのアイコンループ・光の 縁取り演出`
- v1.0.8として公開

### 目的

呼吸法モーダルへの入り口に、追加の演出ステップや高さを増やさずに 「クリックすると異なる次元へ進む」気配を持たせる。

### 所感

今回最大の学びは、**光の縁取り演出で実装方式そのものを2度変えた判断**。 同じ方式（SVG回転）のままパラメータだけを調整し続けていたら、恐らく 「見えない」問題を解決できないまま長く迷走していた可能性が高い。 Codexに「なぜ見えないのか」を先に調査させ、原因（クリッピング）を 明確にした上で、それでも改善しなければ「方式自体を変える」という判断を 早めにできたのが良かった。

また、「回転して一周する」という動きは、イージング（緩急）によって 「遅くて気になる／速くてびっくりする」の両方の問題を生みやすいという 発見も大きい。「回転」ではなく「明滅（呼吸）」に切り替えたことで、 速度のムラという根本問題自体が消え、あとは強さの微調整だけで済んだ。 今後、類似の演出を検討する際は、最初から「回転させない」表現を優先的に 検討する価値がありそうだ。

## 2026-08-13〜17 呼吸パターンのカスタマイズ（ISS-041）

### 概要

マインドフルネス瞑想の呼吸法を、4・7・8呼吸固定から腹式呼吸（デフォルト）・4・7・8呼吸法・ボックスブリージング・数息観の4種から選択できる形に改修。v1〜v13までクロコ（Claude）との設計レビューを重ね、Codexで実装。

### 実施内容

**設計・分岐ロジック**

- 既存の`startBreathCycle(phases)`が「ISS-041から別の配列を渡せるよう」設計されていたことを確認し、478・ボックスブリージングは既存ロジックをそのまま流用。腹式呼吸（明滅のみ）・数息観（タップ駆動）は別経路として新設
- `BREATH_PATTERNS`のconfigオブジェクトで4パターンを管理する設計に統一

**UIの試行錯誤（v1〜v13）**

- 呼吸法選択カードを常時4枚表示 → スマホで1画面に収まらず、開閉式（アコーディオン）メニューに変更
- 時間選択を呼吸法メニューに統合 → 「閉じ方が分からない」問題が発生し、時間選択を独立UIへ切り戻し、選択したら自動で閉じる挙動に戻す、という方針転換あり
- 各呼吸法の説明文を簡易版→「効果／方法／コツ」の3項目形式に拡充。中央揃え→左揃え、ラベルを「呼吸の方法」→「方法」に短縮してコロン位置を揃えるなど、可読性を段階的に改善
- ボックスブリージングの視覚的なガイドについて検討したが、既存の円形リング＋フェーズ配列駆動の仕組みを維持する形で決着
- 数息観は「ひー・とー・つー」の読み仮名をタップごとに表示。表示テンポを2段階で緩和し、中黒（・）を廃止して字間（letter-spacing）で表現
- ⓘアイコンから開く「基本の姿勢」パネルを新設（呼吸法選択パネルとは独立、常時非表示）
- レイアウト調整の過程で縮小されていたスタート/リセット・BGM選択ボタンのサイズを、デプロイ済み版と比較しながら是正

**ドキュメント整合性の発見・修正**

- ISS-035〜044のドキュメント欠番対応中、Excel（次の停車駅）のID列が行挿入により過去にズレていたことが判明。原因はID列が`="ISS-"&TEXT(ROW()-1,"000")`という行番号連動の数式だったこと
- Vault内の実ファイル（ISS-025/027/028/030など）とのクロスリファレンスを正として、Excelを訂正（IDを固定値化、023/025/027/028/030の番号ズレを是正）
- 完了画面の不要な確認ダイアログ（ISS-045）、BGM音量のバランス調整（ISS-046）を、スコープが異なる別ISSとして切り出し

**Netlifyのデプロイ最適化**

- Obsidianのdocs更新のたびにNetlifyの無料ビルド枠が消費される問題に対応し、`netlify.toml`の`ignore`設定で、docs/配下のみの変更はビルドをスキップするよう設定

**Commit・Push**

- Commit `aabdd0f`：`feat(ISS-041): 呼吸パターン選択を拡張`
- v1.0.9として公開

### 目的

呼吸のペースが合わない、7秒止めるのが負担、といった個人差に対応し、瞑想機能の離脱要因を減らす。あわせて、選択画面自体が新しいユーザーへのマインドフルネス瞑想の入り口（簡易的な解説）としても機能するようにする。

### 所感

今回最大の学びは、UIの反復レビュー（v1〜v13）そのものよりも、**ドキュメントの整合性が崩れていたことへの気付きと対処**だった。Excelの数式ベースID列が、行挿入のたびに静かにズレていくという構造的な問題は、実害が出るまで気付きにくい類のもの。今回はISS-041の関連ISSを辿る過程で偶然発覚したが、Vault内の実ファイル（MDの相互参照）の方が、Excelよりも信頼できる「正」として機能した、という点は今後の運用に活かせる教訓。ExcelはID・状態・優先度だけを持つダッシュボードに徹し、詳細と依存関係はMD側を正とする、という役割分担を今後も意識したい。

また、UI設計面では「時間選択をメニューに統合する」という一度採用した方針を、実際に触ってみて「閉じ方が分からない」というフィードバックを受けてすぐに撤回した判断が良かった。設計は一度で決め切ろうとせず、実物を見て軌道修正する前提で進める方が、結果的に早く収束する。
