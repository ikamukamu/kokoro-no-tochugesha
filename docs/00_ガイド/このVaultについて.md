# このVaultについて

このノートは「ココロの途中下車」開発ナレッジベース（Obsidian Vault）全体の
構成と目的を管理するハブページです。迷ったらまずここに戻ってください。

## Vaultの目的

「人とAIが同じ情報を参照しながら、安全かつ一貫性のある開発を継続できる状態を
維持すること」を目的として運用しています（詳細は [[開発ルール]] を参照）。

GitHubリポジトリの `docs/` フォルダそのものがこのVaultであり、GitHub上の
`docs/` が正本、Obsidianはそのエディタという位置づけです。

## このVaultの考え方

このVaultは「ドキュメント置き場」ではなく、
設計意図・判断理由・運営ノウハウを人とAIで共有する
ナレッジベースとして育てていく。

新しい知見や設計判断が生まれたら、
コードだけでなく関連するノートも更新することを基本とする。

## 構成

```
docs/
├─00_ガイド
├─01_PBL
├─02_ISS
├─03_設計
├─04_開発ログ
├─05_運営
└─ekicho-dayori
```

※ `ekicho-dayori/` のみ番号体系の外に置いている。駅長だよりは制作物（原稿・pptx・素材）が
セットで溜まっていくため、運営ノートとは分けて独立フォルダで管理する。

### 00_ガイド ─ プロジェクトの土台となる情報

- [[開発ルール]]：GitHub運用・AI利用ルール・バージョン管理などの人向けルール集
- [[開発フロー]]：アイデア発生からPush・デプロイまでの全体フロー（図・Mermaid）
- [[命名規則]]：ISS番号・アセットファイルなどの命名ルール

### 01_PBL ─ バックログとタスク一覧

- [[ISS一覧]]：全ISSへの索引（状態・概要つき）
- [[次の停車駅]]：バックログの運用ルール（優先順位・状態の定義・PBL.xlsxへの導線）

### 02_ISS ─ 個々のタスクの詳細

- [[ISS-031]]：マイコーピング再構成（基盤整理）
- [[ISS-032]]：マイコーピング再構成（ISS-031依存の機能追加）
- [[ISS-033]]：マイコーピング再構成（regression scope広め、033a/033b分割検討）
- [[ISS-034]]：マイコーピング再構成（データ移行を伴う機能）

現在進行中の依存関係：ISS-031 → ISS-032、ISS-033・034は並行検討可。

### 03_設計 ─ 仕様・世界観・デザイン

- [[世界観]]：理念・世界観・駅長やNR赤坂Stなどの世界観設定
- [[デザインガイド]]：ロゴ・カラー・デザインルール
- [[システム構成]]：システム全体の構成と各サービスの役割
- [[ホーム画面]]：ホーム画面の設計仕様
- [[コーピング]]：マイコーピング機能の設計仕様

### 04_開発ログ ─ 開発の記録

- [[2026-07]]：2026年7月分の開発ログ

月別にノートを分割し、実施内容・目的・所感を記録する。

### 05_運営 ─ サービス運営に関する情報

- [[VOC]]：利用者からの感想・要望・フィードバック
- [[リリース履歴]]：公開したバージョンと変更内容
- [[アカウント一覧]]：利用サービスのアカウント情報（※認証情報は書かない）
- [[契約ライセンス]]：契約中のサービス・ライセンス情報

### ekicho-dayori ─ 駅長だよりの制作

毎月発行する A4片面ニュースレター「駅長だより」の企画・制作物一式（`docs/ekicho-dayori/`配下）。

- `_template.md`：号の雛形（構成・レイアウト方針の正本）
- `assets.md`：使い回す素材・配色・フォーマット仕様
- `NN_yyyy-MM.md`：各号の原稿（発行メモ・本文・制作メモ）
- `#N_vN.pptx`：レイアウト作業用ファイル

## 運用ルールの要約

- 新規の設計意図の確認は `01_PBL → 02_ISS → 03_設計 → コード` の順で行う
- 秘密情報（パスワード・APIキー等）はVault内に一切書かない（パスワードマネージャーへ）
- 詳細な記述ルールは [[開発ルール]] の「ドキュメント管理」を参照
